# Spec 02：消除 FA decode 的 KV 重复读取（按 kv 头分组）

> 项目：Ai_edge_deployment（llama.cpp CPU 特化 fork）
> 日期：2026-09-26
> 状态：**已实现，验收部分通过**（R1/R4/R6/R7 通过；**R2/R3/R8 未达标**，见 §9）
> 上游基线：`5096f2a` + `c649f60`
> 证据：`ctest/benchmark_results.md` §12（根因）、§12.7（路径与量化 V 分离实验）、**§13（实测结果）**

---

## 0. 一句话

把 CPU flash attention 的 decode 内核从"每个 q 头各扫一遍 KV"改成
"每份 K/V 读一次、喂给同一个 kv 头下的全部 q 头"，把 KV 流量乘数 α 从 GQA 比降到 1。

---

## 1. 需求的具体化

原始诉求是模糊的（"FA 在长上下文太慢，查一下"）。本 spec 把它拆成**可判定条款**。
每条都必须能被 §6 的测试机械地判成通过/不通过，不接受"大致""差不多""应该是"。

| 编号 | 条款 | 判定方式 |
|---|---|---|
| **R1** | 新实现在每个 q 头上的输出与改动前**逐位相同**（bit-exact） | 同 prompt、`--temp 0`、逐 token 比对；四组必测 |
| **R2** | ctx=8192 / t=12，**同批次** FA 相对 legacy 的比值 ≥ **0.95** | 同批对照，不用绝对值（避免跨批次漂移） |
| **R3** | V 为 f16/f32 时，ctx=8192 反推 α ≤ **1.15** | §6.3 公式，不得目测 |
| **R4** | ctx ∈ {256, 512, 1024, 2048, 4096} 的 FA 速度不低于改动前 ×0.95 | 逐点对比 |
| **R5** | 不得改变内核路径选择条件；不满足前提必须**回落到现有实现** | 代码审查 + §6.4 矩阵 |
| **R6** | 提供 env 开关，不重编译即可回到改动前行为 | `LLAMA_FA_GQA=0` |
| **R7** | 路径 A（`nek1>=512`）与路径 B（其余）**两条都要受益** | §6.4 矩阵两项各自达标 |
| **R8** | `-fa 1 -ctk q8_0 -ctv f16` @8192：**同批次 ≥ legacy 同配置 ×0.95** | 今天该配置是 17.3 vs legacy 22.8（比值 0.76） |

### 1.1 明确排除：量化 V 不是本次目标

**`-ctv q8_0` 在 FA 下有一个与本次根因无关的独立缺陷**（§12.7）：
把 V 从 f16 换成 q8_0，字节数减半，速度反而从 17.3 掉到 **10.5**（−39%），
反推 α 从 1.95 跳到 **5.37**。修复 GQA 重读**不会**修好这个（它消除的是那个 ×2，
剩下仍有 ~2.7× 的额外开销）。因此：

- 本次**不承诺** `-ctv q8_0` 的任何收益，R8 用的是 **V=f16** 的合法配置
- 该缺陷单独立项为下一步（见 §7），不在本次验收范围

## 2. 现状：CPU FA decode 的两条路径（已确认，非推测）

`llama-graph.cpp:2633` 调用前对 q/k/v 做 `ggml_permute(0,2,1,3)`，传入
`k: ne=[head_dim, n_kv, n_head_kv, 1]`，故 **`nek1 == ctx`**。
入口 `ggml/src/ggml-cpu/ops.cpp:9212`：

**路径 A — `use_split_kv_path`（:9261）**
条件 `neq1==1 && neq3==1 && kv 为 f32/f16 && k.type==v.type && q.type==F32 && nek1>=512`
→ 线程按 **KV 分块**（`chunk_size=(nek1+nth-1)/nth`），每线程遍历**全部** q 头。

**路径 B — else 分支（:9300 起）**
线程按 **q 行分块**（`nr=neq1*neq2*neq3`，`nth_scaled=nth*4`）。
覆盖：ctx<512、**KV 被量化**、`k.type != v.type`、`q.type != F32`、`use_ref`。
decode 时 `use_tiled` 恒不成立（需 `neq1>=Q_TILE_SZ`）→ 落到 `one_chunk(..., 0, nek1, nullptr, 0)`。

### 2.1 根因（简要，详见 §12）

`rk2 = neq2/nek2`（每 kv 头服务的 q 头数 = GQA 比），`ik2 = iq2 / rk2` →
**同一 kv 头下的每个 q 头把该 kv 头的同一段 K/V 各扫一遍**。
路径 A 是同线程内重复扫描，路径 B 是不同线程重复扫同一块内存。
`one_chunk` 内部循环序为 `for(ir=q rows){ for(ic=n_kv){...} }` —— q 头在外、KV 在内。

### 2.2 本次新增的分离实验（0.6B Q2_K，ctx=8192，t=12，n=96）

`BW_eff(t=12) = 23.6 × 1.213 = 28.6 GB/s`（由 legacy f16 标定）

| 配置 | 路径 | tok/s | 名义字节/token | 反推 α |
|---|---|---|---|---|
| FA f16 / f16 | A | 12.5 | 1.213 GB | 2.20 |
| FA **q8_0 / f16** | B | **17.3** | 1.001 GB | **1.95** |
| FA **q8_0 / q8_0** | B | **10.5** | 0.765 GB | **5.37** ← 独立缺陷 |
| legacy f16 / f16 | — | 23.6 | 1.213 GB | 1.00（基准定义） |
| legacy q8_0 / f16 | — | 22.8 | 1.001 GB | 1.06 |
| ctx=256 FA f16（强制路径 B） | B | 76.0 | — | 小 ctx 下被缓存吸收 |
| ctx=256 legacy f16 | — | 73.6 | — | FA 仍略快 |

**读出来的三条事实：**

1. **路径 A 与路径 B 的 α 都是 ≈2（= GQA 比）** —— 路径 B 没有额外的结构惩罚。
   所以修复必须**同时覆盖两条路径**，否则量化 K 的配置（走 B）拿不到收益。
2. **量化 K 是有收益的合法配置**：FA q8_0/f16 已经是 17.3，比 f16/f16 的 12.5 快 38%。
   它是本次性价比最高的目标配置。
3. **量化 V 是另一个问题**：见 §1.1。

## 3. 设计

### 3.1 新内核函数

在 `one_chunk` 之后、`_tiled` 之前新增：

```cpp
static void ggml_compute_forward_flash_attn_ext_f16_gqa(
        const ggml_compute_params * params,
        ggml_tensor * dst,
        int64_t ir0, int64_t ir1,          // q 行范围，必须按 kv 头组对齐
        int64_t ic_start, int64_t ic_end,  // token 范围
        float * partials, int64_t partial_stride);
```

```
rk2 = neq2 / nek2
for g in [ir0/rk2, (ir1+rk2-1)/rk2):              // kv 头组在外
    h0 = max(ir0, g*rk2); h1 = min(ir1, (g+1)*rk2)
    for h in [h0,h1):  q_to_vec_dot(pq(h), Qq[h-h0], DK)   // Q 转换提到组外，调用次数不变
    初始化 M[·]=-inf, S[·]=0, VKQ[·]=0
    for ic in [ic_start, ic_end):                          // token 在内
        ptrK = k->data + ic*nbk1 + g*nbk2 + ik3*nbk3       // 只读一次
        ptrV = v->data + ic*nbv1 + g*nbv2 + iv3*nbv3       // 只读一次
        for j in [0, h1-h0):
            s = kq_vec_dot(DK, &s, 0, ptrK, 0, Qq[j], 0, 1)
            ... 与 one_chunk 逐行相同的 scale / softcap / mask / 在线 softmax / vec_mad ...
    收尾：VKQ16→VKQ32、sinks、归一化、写 dst 或写 partials
```

- ic 循环体的算术**逐行照搬**，不得顺手改写
- 同时存活的累加器 ≤ rk2 个（本机 2~4），栈上定长数组即可，**不改 wdata 预算**
- partials 布局 `[q_head][kv_chunk][M,S,VKQ]` 不变 → `reduce_partials` 零改动

### 3.2 路径 A 接入

`:9278-9281` 的 `for (q_head) one_chunk(...)` 换成单次调用
（`ir0=0, ir1=neq2`，天然按组对齐）。`ic_start >= nek1` 的空分支保持原样。

### 3.3 路径 B 接入

使 chunk 边界**按 kv 头组对齐**：可分组时令 `dr` 取 `rk2` 的整数倍、`nchunk = ceil(nr/dr)`，
并跳过原有的 `if (nchunk < nth) nchunk = nth;`（它会破坏对齐）。
每线程得到一个完整组后调用同一新内核，`ic` 取全区间 `[0, nek1)`。

**已知取舍**：`nth > nek2` 时（本机 nth=12、nek2=8）路径 B 的并行度会从 16 降到 8。
这是带宽受限而非算力受限的工作（α 减半 >> 并行度减少），预期净赚，
但**必须实测判定**（§6.4 的 ctx=8192 + q8_0/f16 那一项就是为此存在的）。

### 3.4 回落条件（任一成立则走原 `one_chunk`）

精确列举，不允许"应该可以"：

1. `neq1 != 1 || neq3 != 1`（非纯 decode）
2. `rk2 <= 1`（无复用可赚）
3. `neq2 % nek2 != 0`，或 `nek2 != nev2`，或 `rk2 > 16`（编译期上限）
4. `[ir0, ir1)` 未按 `rk2` 对齐（路径 A 恒满足）
5. `params->use_ref` 为真
6. `LLAMA_FA_GQA=0`

### 3.5 bit-exact 论证（R1 的依据）

对任意 q 头，下列在新旧实现中都**不变**：`ic` 遍历顺序（升序）、每个 `ic` 上 `s` 的计算顺序、
`M/S/VKQ` 的更新顺序、归一化与写出。`Qq` 转换结果不变（只是从"每头各一次"挪到"组开始一次"，
次数与实参相同）。**加法/乘法结合律未被改变 → 结果逐位相同，不是"近似相同"。**

这一点是硬需求而非锦上添花：本项目 `llama-perplexity.exe` 在本机 segfault（exit 139），
**没有客观 PPL 手段**，bit-exact 是唯一不依赖 PPL 就能钉死正确性的办法。

> **勘误（2026-09-27，验收完成后）**：segfault 的根因是 2025-09-25 的
> `llama-perplexity-impl.dll` 为残次构建产物，重编后 PPL 正常。本 spec 的 R1 结论不受影响
> （bit-exact 依然比 PPL 强），但**后续 spec 不再被"无 PPL"约束**，非 bit-exact 方案可用
> PPL + 生成对照验收。见 `benchmark_results.md` §11.6 勘误。

### 3.6 开关

```cpp
const char * env_gqa = getenv("LLAMA_FA_GQA");
const bool allow_gqa = !(env_gqa && atoi(env_gqa) == 0);
```

| 风险 | 说明 | 处置 |
|---|---|---|
| 路径 B 并行度降到 8 | nth > nek2 时部分线程空闲 | §6.4 的 q8_0/f16 项实测判定；不达标则改走"放宽 `kv_is_f32_or_f16`、让更多配置进 split_kv"的第二阶段 |

## 6. 验收标准（本 spec 即这张 fork 的检验卡）

### 6.1 正确性（R1）——一票否决

`--temp 0 -n 256`，改动前后生成的 token 序列必须**完全一致**：

| 模型 | 量化 | `-fa` | ctx |
|---|---|---|---|
| Qwen3-0.6B | f16 | 1 | 512 / 8192 |
| Qwen3-0.6B | Q2_K | 1 | 8192（含 `-ctk q8_0 -ctv f16`） |
| Qwen3-4B | q4_k_m | 1 | 8192 |
| Qwen3-0.6B | Q2_K | 0 | 8192 |

`-fa 0` 组确认 legacy 未被波及。**任何一处不一致即整份判定不合格**，
不得以"浮点误差可接受"结案 —— 按 §3.5 本修改必须是 bit-exact 的，不一致说明实现有误。

### 6.2 性能（R2 / R4）

平台 Qwen3-0.6B Q2_K，`-t 12`，`-n 128`，`-f ctx_<N>.txt`。
每点两侧交替跑 3 轮取中位数，**全部用同批次比值判定**（不跨批次比绝对值）：

| ctx | KV 配置 | 路径 | 硬门槛 |
|---|---|---|---|
| 256 | f16 | B | ≥ 改动前 ×0.95 |
| 512 / 1024 / 2048 | f16 | A | ≥ 改动前 ×0.95 |
| 4096 | f16 | A | ≥ 同批 legacy ×0.90 |
| **8192** | f16 | A | **≥ 同批 legacy ×0.95**（today 0.52） |
| **8192** | `-ctk q8_0 -ctv f16` | B | **≥ 同批 legacy 同配置 ×0.95**（today 0.76） |

单点不达标必须给出物理解释，并作为已知边界写进 `benchmark_results.md`，不得静默略过。

### 6.3 α 是否真的降到 1（R3）

必须用**同批次、同线程数**的 legacy 当带宽基准（消除"线程多了带宽也涨"这个混淆变量）：

```
W      = 325 MiB                                   （模型本体）
K      = ctx × kv_bytes_per_token                  （f16 = 112 KiB；K 量化时按实际算）
BW_eff = legacy_speed × (W + K)                    （由 legacy 标定，α≡1）
α      = ( BW_eff / FA_speed − W ) / K
```

判定：**V 为 f16 的配置，ctx=8192 反推 α ≤ 1.15**（today 2.20）。
并复跑 t ∈ {4, 8, 12, 16} 的 α 曲线 —— 修复后 α 应对线程数**基本不敏感**；
若仍随线程数大幅变化，说明还有未消除的重复读取，继续查而不是结案。

### 6.4 覆盖矩阵（R5 / R7）

全部跑通且不留空：

| 场景 | 路径 | 期望 |
|---|---|---|
| decode ctx=8192, f16 KV | A + 新内核 | 提速 |
| decode ctx=8192, `-ctk q8_0 -ctv f16` | B + 新内核 | 提速（R8） |
| decode ctx=256, f16 KV | B + 新内核 | 不回退 |
| decode ctx=8192, `-ctv q8_0` | B + 新内核 | **不承诺收益**，但不得比改动前更慢 |
| prefill（`llama-bench -p`） | tiled / 回落 | 与改动前一致（±噪声） |
| `-n 1`、batch>1 | 回落 | 与改动前一致 |
| `LLAMA_FA_GQA=0` | 全部回落 | 与改动前逐位一致 |

### 6.5 代码质量

- 不得整段复制 `one_chunk` 再改：重复部分要么提取公共内层，要么注释说明为何必须重复
- 每个新增分支都要写清**为什么这个条件必须回落**
- 不在热点路径上新增日志、分配、`getenv`（`getenv` 每次 op 入口只允许一次）

## 9. 验收结果（实现后回填，本卡据此判定）

测试方式：为避免跨批次漂移，性能一律用**同一二进制内 `LLAMA_FA_GQA=0`（回落）与默认（分组）
交替各跑 2 次**；正确性用 `bin-base`（改动前编译产物）与 `bin-gqa` 逐 token 比对。
平台 Qwen3-0.6B Q2_K，`-t 12`，`-n 128`，ctx=8192 用 `-f ctx_8192.txt`。

### 9.1 实测数据

| 配置 | 路径 | 关闭 | 开启 | 变化 | 同批 legacy |
|---|---|---|---|---|---|
| KV f16/f16 @8192 | A | 11.35 | **12.95** | +14% | 20.0 |
| `-ctk q8_0 -ctv f16` @8192 | B | 14.75 | **17.85** | +21% | 22.0 |
| `-ctk q8_0 -ctv q8_0` @8192 | B | 14.6 | 14.6 | 0 | — |
| KV f16 @256 | B | 81.0 | 79.9 | −1.4% | — |
| KV f16 @512 | A | 74.9 | 73.6 | −1.7% | — |

（`-ctv q8_0` 一项在首轮实现中实测 **−10%**，已按 §1.1 加入回落条件，现为 0；见 §9.3）

### 9.2 条款判定

| 编号 | 门槛 | 实测 | 判定 |
|---|---|---|---|
| R1 bit-exact | 6 组全部逐位一致 | 6/6 IDENTICAL（含 4B q4_k_m @8192） | **通过** |
| R2 f16 @8192 ≥ legacy×0.95 | 0.95 | **0.65** | **不通过** |
| R3 α ≤ 1.15 | 1.15 | 2.09 → **1.78** | **不通过** |
| R4 ctx≤4096 不回退（×0.95） | 0.95 | 256: 0.986 / 512: 0.982 / 1024: 0.974 / 2048: 0.983 / 4096: 1.012 | **通过** |
| R5 回落条件精确列举 | 代码审查 + 矩阵 | 已列举 7 条；prefill 实测 156.6 vs 161.1（噪声内，分组内核不参与） | **通过** |
| R6 env 回滚 | `LLAMA_FA_GQA=0` | 生效，且与改动前逐位一致 | **通过** |
| R7 两条路径都受益 | A 与 B 各自达标 | A +14%、B +21% | **通过** |
| R8 q8_0/f16 @8192 ≥ legacy×0.95 | 0.95 | **0.81** | **不通过** |

### 9.3 实现过程中对本 spec 的两处修订

1. **新增回落条件：V 被量化时不分组**（首轮实测 −10%）。
   根因：分组内核只把 V 的**加载**提到组外，**反量化仍按 q 头各做一次**，
   且共用一个 V32 缓冲引入了写后读串行。量化 V 另有独立缺陷（§12.7），
   按 §1.1 排除而非半修。
2. **路径 B 的并行度损失已实测确认**：`nth > nek2` 时按组切分使并行度从 16 降到 8，
   ctx=8192 的 q8_0/f16 上净收益 +21%（说明流量减半的收益 > 并行度损失），
   短上下文损失仅 1.4~1.7%。

### 9.4 仍未测项（不得当作通过）

- §6.4 的 batch>1、`-n 1` 矩阵
- R3 的"α 对线程数不敏感"复跑：α 本身已不达标，该项暂缺
- `-ctv q8_0` 的速度：该配置在本机**无法稳定测量**（同一命令同一二进制跨度 3.0~15.3 tok/s），
  只保留"已加回落条件 → 与改动前同路径"这一代码层面的保证，不下速度结论

### 9.4.1 测量纪律（本次踩坑，以后必须遵守）

长上下文 benchmark **必须串行零并发**。本次在前一个后台任务未结束时提交了下一批，
导致 ctx=2048 测出 4.4 而 ctx=4096 测出 7.9（物理不可能）、量化 V 复检出现 4.5/3.0，
全部作废重测。**后台任务的完成通知到达前，不得提交下一批。**

### 9.5 结论：本 spec 的根因假设不完整（重要）

按 §3 的设计，消除 GQA 重读应把 KV 流量乘数从 GQA 比（2）降到 1，
ctx=8192 的 FA 应从 11.35 提到约 24（≈legacy）。**实测只有 +14%。**

反推：修复后若 α 真为 1，则 12.95 tok/s 对应
`12.95 × (0.317 + 0.896) GB = 15.7 GB/s`，而同一批次 legacy 达成 `20.0 × 1.213 = 24.3 GB/s`
→ **FA 只拿到 legacy 65% 的带宽效率**。

两种可能解释（尚未区分，必须实测而非择一采信）：
1. 重复读本来就被 L2 吸收（每线程每 kv 头组 683 token × 512 B = 350 KB，进 L2），
   所以"去掉重复读"省下的本来就不多 —— 那么 α≈2 这个拟合值也就不代表真实 DRAM 流量；
2. FA 的流式内核本身达不到 `mul_mat` 的 DRAM 效率（去掉重复读后仍差 35%）。

两者都指向同一结论：**α 作为判据已经失效，§12 用 α 得出的"GQA 重读是主因"不成立 ——
它只是 FA 长上下文惩罚的一小部分。** 下一步必须直接测量 DRAM 流量或用受控实验区分，
不得再靠 α 拟合下结论。

### 9.6 收益重估

| 项目 | spec 预测 | 实测 |
|---|---|---|
| ctx=8192 FA f16 | ~24（追平 legacy） | 12.95 |
| ctx=8192 FA q8_0/f16 | ~22 | 17.85 |
| 相对改动前 | +90% | +14% / +21% |

本改动**保留**（bit-exact、无回退、+14~21%），但它**没有**兑现"让 FA 追平 legacy"，
因此 §11 那个 +35% 仍然拿不到，且现在可以确认：**瓶颈不在 §12 所指的位置。**
